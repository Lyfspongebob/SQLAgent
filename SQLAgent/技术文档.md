# SQL Agent 智能SQL助手 - 技术文档

> 知识库 RAG 部分已于 2026-10-20 改为显式检索方案。本文中涉及 `tools.retrieval` 的旧描述仅保留作历史参考，当前实现请见 [知识库RAG技术文档.md](知识库RAG技术文档.md)。

## 一、项目概述

SQL Agent 是一个基于大语言模型的智能SQL助手系统，支持自然语言查询数据库、知识库检索、SQL多投定优与Agent反馈修正等核心功能。系统采用前后端分离架构。

### 技术栈

## 三、后端模块详解

### 3.1 核心引擎 - SQLAgentService

**文件**: `agent/SQLAgentService.java`

核心处理流程：

```
用户消息
  │
  ├─ 1. 知识库查询（如启用）
  │     └─ 调用智谱对话API + tools.retrieval
  │
  ├─ 2. SQL Agent模式（如启用）
  │     ├─ 获取数据库表结构
  │     ├─ SQL多投定优（生成N个候选SQL）
  │     ├─ 执行所有候选SQL并投票
  │     ├─ 成功 → 返回最佳结果
  │     └─ 失败 → Agent反馈修正（最多3次重试）
  │
  └─ 3. 普通对话模式
        └─ 调用DeepSeek Chat
```

**关键特性**:

#### 特性一：SQL多投定优机制
- 使用高 Temperature（0.8）生成多个候选 SQL（默认10个）
- 执行所有候选 SQL，根据执行结果投票
- 选择执行成功且结果最多的 SQL

#### 特性二：Agent反馈修正机制
- 所有候选 SQL 都失败时，将错误信息反馈给 AI
- AI 分析错误原因并修正 SQL
- 最多重试 3 次

#### 特性三：知识库 + SQL Agent 协同
- 知识库查询结果作为上下文注入到 SQL 生成的 prompt 中
- 帮助 AI 更准确理解用户意图

### 3.2 AI服务 - DeepSeekService

**文件**: `agent/DeepSeekService.java`

调用 DeepSeek Chat API 提供以下能力：

| 方法 | 用途 | Temperature |
|------|------|-------------|
| `chat()` | 基础对话 | 0.7 |
| `generateSQL()` | 生成SQL（支持知识库上下文注入） | 0.8 |
| `fixSQLWithFeedback()` | 根据错误反馈修正SQL（支持知识库上下文注入） | 0.3 |
| `normalChat()` | 普通对话 | 0.7 |
| `normalChatWithKnowledge()` | 基于知识库内容的润色回答 | 0.7 |

### 3.3 知识库服务 - KnowledgeBaseService

**文件**: `agent/KnowledgeBaseService.java`

通过智谱AI对话API + `tools.retrieval` 实现知识库检索：

```json
POST https://open.bigmodel.cn/api/paas/v4/chat/completions
{
  "model": "glm-4-plus",
  "messages": [{"role": "user", "content": "用户问题"}],
  "tools": [{
    "type": "retrieval",
    "retrieval": {
      "knowledge_id": "知识库ID",
      "prompt_template": "从文档...中找问题...的答案..."
    }
  }]
}
```

### 3.4 数据源管理 - DynamicDataSourceManager

**文件**: `datasource/DynamicDataSourceManager.java`

- 支持动态添加/切换数据源
- 支持 MySQL 数据库
- 自动获取数据库表结构信息

### 3.5 用户认证 - Sa-Token

**文件**: `config/SecurityConfig.java`, `config/SaTokenConfigure.java`

- 基于 Sa-Token 的登录认证
- Token 有效期：7天（604800秒）
- 支持注册、登录、获取当前用户信息

## 七、核心流程详解

### 7.1 知识库查询流程

```
用户开启知识库开关
  │
  └─→ KnowledgeBaseService.queryKnowledgeBase(query)
       │
       └─→ 调用智谱对话API (POST /v4/chat/completions)
            ├─ model: glm-4-plus
            ├─ messages: [{role: "user", content: query}]
            └─ tools: [{type: "retrieval", retrieval: {knowledge_id, prompt_template}}]
                 │
                 └─→ 智谱AI自动检索知识库
                      ├─ 找到相关内容 → AI基于知识库内容回答
                      └─ 未找到相关内容 → AI用自身知识回答（并提示非文档来源）
```

### 7.2 SQL Agent 执行流程

```
用户输入自然语言查询 + 选择数据源
  │
  └─→ SQLAgentService.processSQLQuery()
       │
       ├─ 1. 获取数据库表结构
       │
       ├─ 2. SQL多投定优（循环voteCount次）
       │     └─ DeepSeek生成SQL → 清洗 → 收集
       │
       ├─ 3. 执行所有候选SQL
       │     └─ 投票选择最佳结果
       │
       ├─ 4. 成功 → 返回结果 + 自然语言回复
       │
       └─ 5. 全部失败 → Agent反馈修正（最多3次）
             └─ 将错误反馈给DeepSeek → 修正SQL → 重试
```

### 7.3 知识库 + SQL Agent 协同流程

```
用户同时开启知识库和SQL Agent
  │
  ├─ 1. 查询知识库（智谱AI）
  │     └─ 获取基于知识库的回答
  │
  └─ 2. SQL Agent
        └─ 将知识库回答注入到SQL生成的prompt中
             └─ "以下是知识库中相关的参考信息：..."
                  └─ DeepSeek结合知识库上下文生成更准确的SQL
```

## 九、关键设计决策

### 9.1 为什么使用智谱AI的 tools.retrieval 而不是独立知识库API？

智谱官方推荐通过对话API的 `tools.retrieval` 参数来检索知识库，这种方式的好处是：
- 一次API调用即可完成知识库检索 + AI回答
- 支持自定义 `prompt_template` 控制回答风格
- 知识库无结果时自动用模型自身知识补充

### 9.2 为什么SQL生成使用高Temperature？

- **高Temperature（0.8）**：用于多投定优，生成多样化的候选SQL
- **低Temperature（0.3）**：用于Agent反馈修正，保证修正的准确性

### 9.3 为什么使用双AI模型？

- **DeepSeek Chat**：负责SQL生成、修正、普通对话（成本低、SQL能力强）
- **智谱GLM-4-Plus**：负责知识库检索（智谱知识库生态完善）

## 十、注意事项

1. **API Key安全**：配置文件中的 API Key 请勿提交到公开仓库
2. **数据库连接**：确保 MySQL 服务正常运行
3. **网络要求**：需要能够访问 DeepSeek API 和智谱AI API
4. **知识库ID**：需在智谱开放平台创建知识库并获取对应的 knowledge_id
